# 未见 TF 故障诊断消融

## 实验设置

- 实验 ID：`unseen-transform-frozen-v1`
- 冻结提示词：`diagnostic-structure-v1-frozen`（冻结提交 `a12282f`）
- 模型后端：OpenFang，服务报告模型名为 `default`
- 故障：AMCL lifecycle 保持 `active`，只把真实参数 `tf_broadcast` 设为 `false`
- 现场表现：`map->odom` 动态变换停止更新，Nav2 返回 `Failed to transform end pose to global frame`
- 每组 2 次。样本量很小，结果只描述本次受控实验，不代表统计显著性。
- 注入标签不进入 Agent 上下文；真值仅在 run 终止后写入私有 `experiment_labels` 表。

三组使用同一任务、目标和故障。规则组执行固定诊断；无工具模型只收到任务、目标和 `navigation_attempt`；工具模型可以自行选择 ROS 只读调查工具。三组都经过相同的确定性修复授权器。

## 结果

| 组别 | 未知故障识别 | TF 子系统识别 | 诊断工具/授权复测 | 修复申请 | 授权修复 | 错误修复 | 平均调查时间 | 平均 tokens |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 规则 | 0/2 | 0/2 | 2.0 / 1.0 | 0 | 0 | 0 | 0.023 秒 | 0 |
| 无工具模型 | 1/2 | 1/2 | 0.0 / 1.0 | 1 | 0 | 0 | 9.814 秒 | 5,632 |
| 工具模型 | 2/2 | 2/2 | 6.5 / 1.0 | 0 | 0 | 0 | 13.791 秒 | 27,833.5 |

规则组两次均把现场判为 `healthy`，说明固定枚举没有识别未见机制。无工具模型有一次正确识别 TF，另一次误判为已有的 `localization_drift` 并申请重置定位；授权器用新鲜现场证据拒绝该申请。工具模型两次都检查了变换及其他现场信号，引用 `map->odom` 持续老化、其他变换正常、Nav2 报错及机器人未移动等证据，判定为白名单之外的 TF 故障并升级人工。

全部 6 次 run 都以 `escalated` 结束，没有执行自动修复。这是预期的安全结果，因为该未见故障没有白名单修复。任务完成率为 0 也是预期结果，不应被解释为恢复成功。

工具次数拆成了两个口径：诊断工具由规则或模型在调查阶段使用；授权复测由服务器确定性授权器执行。无工具模型的诊断工具次数确实为 0，它显示的 1 次总工具事件只来自授权复测。

完整逐次输出与结构化 metrics 在 [unseen-transform-ablation.json](./unseen-transform-ablation.json)。

## 边界

- 当前只有一个未见机制、每组两次，不能据此推断一般诊断准确率。
- 工具模型的正确率更高，但 token 和时间代价明显更大。
- 本实验验证了“诊断可开放、执行须授权”的结构，没有验证未知 TF 故障的自动恢复；它被有意升级给人工。
- OpenFang 配置将模型名公开为 `default`，因此结果只能稳定标识后端和提示词版本，不能从结果文件确认其底层供应商模型名称。
