# Assistant 自然语言任务

在页面顶部的“Assistant 自然语言任务”输入完整指令，点击“解析并执行任务”。

```text
让机器人 2 去 (7, 6)
让机器人 1 去 (3, 4)，同时让机器人 2 去 (7, 6)
机器人 2 去 (7, 6)，失败时仅诊断，禁止修复
```

坐标范围是 0.5～10.5，机器人编号为 1、2。当前一次支持每台机器人一个目标，两台任务独立并行。多路点顺序任务、相对移动、未命名地点暂不支持，请直接给出坐标。

## 执行过程

1. Assistant 模型解析出机器人、坐标和是否允许修复。OpenFang 后端为这一步创建独立 assistant 会话，结束后清理；direct 后端使用同一结构化计划协议。
2. 服务端校验计划：未知机器人、越界/非有限坐标、重复机器人、额外字段均不能执行。信息不全时模型应返回补充问题；错误格式返回失败，不降级为猜测。
3. 网关一次锁定整批机器人；其中一台忙碌则整批拒绝，不先移动另一台。
4. 每台机器人执行自己的目标。位置验收成功即结束，不额外调用诊断模型。
5. 导航失败后，对应 RobotAgent 自动调查真实状态。若允许修复且新鲜证据符合白名单，执行修复并重放同一目标。
6. 页面展示计划、目标、运行状态、诊断与位置验收。点击“查看执行结果”或从历史中选任务查看。取消在任务列表中操作。

“允许限定修复”复选框是硬上限：未勾选时即使模型建议修复也不能执行。文本中的“禁止修复”也会交给规划模型解析为不修复；若需要确定地禁用，请取消勾选。
规划 token 单独记录于 plan.usage；每机器人 run.usage 仅含诊断用量，双任务不会把规划用量累加两次。

## 接口

POST /api/assistant/tasks，沿用 X-Lab-Token 写入保护：

```json
{"prompt":"让机器人 2 去 (7, 6)","auto_repair":true}
```

返回 plan 和 run_ids。需补充信息时 run_ids 为空，plan.status=needs_clarification；成功分派为 dispatched。该状态表示已分派，不等于导航成功，执行结果仍看各 run.status。
GET /api/assistant/plans/{id} 可读取持久化计划；原有任务读取、取消、导出接口保持兼容。每个 run 保存分派计划快照和 target，手动诊断仍使用 (8,8)。

每轮规划是一次同步模型请求，页面显示“正在解析”，此阶段尚无可取消的机器人 run；请求超时会失败。机器人任务开始后沿用原有取消机制。页面刷新会恢复所选计划，最近 30 个计划可从下拉框查看。未提交的输入不会保存。未完成计划在服务重启后标记 interrupted，不自动执行。

信息不全时，在原输入框补充后点击“补充并继续”。例如先输入“让机器人 2 移动”，再补充“去 (7,6)”。接口续接时传入 `parent_id`；服务端保留上下文，最多 5 轮用户输入，不能扩大原计划的修复权限。已续接的父计划不能再次提交；点击“新建指令”开始独立任务。

## 边界

这是支持有限澄清续接的自然语言导航规划 + 本地调度网关，不是通用聊天机器人，也未使用 OpenFang 原生 agent-to-agent 调度。目标来自结构化模型结果，语义理解仍可能出错；当前仅用于本机仿真。持续故障监控、跨机器任务租约、Gazebo/Nav2、自动代码修复、实体机器人均不在本次实现中。
