# 项目表达

## 一句话

Robot Debug Lab 把 Gazebo/Nav2 导航失败组织成“真实复现、AI 工具调查、证据核验、受限恢复、同任务回归”的可追溯闭环。

## 简历描述

- 基于 ROS 2 Lyrical、Gazebo Sim 与 Nav2 搭建仓库机器人导航现场，设计可控激光数据边界，稳定复现“传感器仍在线但导航输入中断”的跨节点故障。
- 接入 OpenFang Agent，将节点图、话题速率、参数和运动采样封装为只读工具；实现结构化诊断、真实证据 ID 引用、调用预算与错误显式传播。
- 实现确定性原子任务与 ReAct 复杂任务的分层入口：模型批量核验真实语义地点和机器人能力，生成多步骤任务；网关校验跨步骤业务约束，能力不足时提出替代方案并通过多轮澄清重规划，不虚构动作完成。
- 设计确定性执行网关：用新鲜观测校验模型建议，只开放白名单恢复动作，并以 Gazebo 里程计误差独立验收同目标重放结果。
- 实现任务级路线恢复：Gazebo 实体阻塞默认接近点后，Agent 基于任务进度和真实 Nav2 可达性选择审核过的备用接近点，网关保留其余步骤并对修订计划重新验收。
- 实现复杂任务中途故障恢复：确定性装置在指定 Nav2 调用触发真实故障且不向 Agent 暴露标签，系统保留前序步骤、用现场证据执行匹配修复、重放失败步骤并继续后续任务；三轮 18 项 AI/规则真实矩阵全部恢复、错误修复为 0，并分别统计规划与诊断 token。
- 实现同一步分层恢复：先由诊断 Agent 识别并修复 Nav2 lifecycle 故障，原目标重放遇到 Gazebo 实体阻塞后重新验证系统健康，再由路线 Agent 基于任务状态和 Nav2 可达性选择备用接近点；真实组合验收完成 5/5 步，最终误差 0.182 m。
- 增加 AMCL 定位漂移机制：通过 ROS `/initialpose` 形成与 Gazebo 真值可测量的位姿分离，Agent 交叉排除雷达、lifecycle 和 controller 故障，网关只允许仿真专用 AMCL 重新播种；独立任务和复杂任务中途的 AI/规则对照均恢复成功、错误修复为 0。
- 接入第二台真实Gazebo TurtleBot3与独立命名空间Nav2，按机器人隔离雷达、定位、任务锁、故障和诊断Agent上下文；车队OpenFang Agent读取实时位置与健康状态后提出分工，确定性网关执行原子批次和唯一充电站约束。原生GUI验收中两台机器人并行完成货架A与充电站任务，Gazebo误差分别为0.236 m和0.037 m。
- 实现可审计的跨机器人任务接替：一台机器人故障未恢复时保留其失败记录，健康机器人完成原任务后仅接手可迁移的剩余步骤，并以独立运行和Gazebo误差重新验收；真实雷达中断实验中接替完成2/2步，误差0.126 m，接替阶段不调用模型。
- 实现 React 实时调试台、SSE 事件流、SQLite 历史、规则基线与 AI 对照，以及 JSON 证据导出。
- 构建 Nav2 真实源码隔离实验，使用 ASan/UBSan 复现越界问题，限制 AI 补丁作用域并通过重新编译和 6 个独立场景验证候选。

## 面试时怎么讲

先演示规则基线，证明故障装置和修复链路可靠；再演示 AI 模式，展开时间线说明模型如何选择工具、引用证据和消耗 token。重点解释为什么模型不进入速度控制环，以及为什么最终结果由 Gazebo 里程计判定。

不要称它为生产车队调度系统或通用自愈平台。当前范围是两台本地仿真机器人、四种可控ROS/Nav2故障、有限任务动作和小样本功能验收。它证明的是复杂任务编排、车队状态查询、原子并行分派、Agent工具边界、故障隔离、证据链、同任务恢复和受限任务接替能力；尚未证明大样本稳定性、通道预约与死锁解除、任意任务迁移或实体货物操作。
